# Research: Langfuse — Deep Dive for HandoffGraph Gap Analysis

*Researched 2026-08-27. Facts verified against the GitHub API, langfuse.com docs, the langfuse/langfuse repo (incl. the live `docker-compose.yml` on `main`), engineering blogs, and issue trackers.*

## Summary

Langfuse is the flagship open-source (MIT-core + enterprise-EE folders) "AI engineering platform" — LLM tracing/observability, prompt management, datasets/experiments, and evaluations — originally a YC W23 startup, seed-funded ($4M, Nov 2023), and **acquired by ClickHouse on 2026-01-16**. Its V4 architecture is an observations-first, wide immutable ClickHouse table fed by an S3-buffered, Redis/BullMQ-queued ingestion pipeline, with Postgres for transactional data. It is very large (33.8K stars, ~200+ verified contributors, >5B events/month on cloud) and its most transferable lessons for HandoffGraph are its OTel-native ingestion contract, denormalized wide-event read model, prompt versioning/labels, universal "scores" primitive, and MCP-server-first AI assistant — while its weaknesses (heavy 6-service self-host stack, no coding-agent focus, no evidence/verification story, LLM-dependent AI features) are exactly HandoffGraph's home turf.

## 1. Position & pitch

1. **What it is** — "Open source AI engineering platform: LLM evals, observability, metrics, prompt management, playground, datasets," positioned as the debugging/improvement loop for LLM applications: *Develop* (tracing, UI, prompt management) → *Monitor* (traces, analytics, metrics, evals) → *Test* (experiments, releases, datasets). [README](https://github.com/langfuse/langfuse), [langfuse.com](https://langfuse.com)
2. **Who uses it** — thousands of teams on Langfuse Cloud (multi-tenant); named customers include **Canva, Samsara, Twilio, Khan Academy, Intuit**; widely adopted by OSS LLM projects and by engineers who want a self-hosted LangSmith alternative. [Careers](https://langfuse.com/careers), [Enterprise](https://langfuse.com/enterprise)
3. **Value prop (one paragraph)** — Langfuse gives product/ML teams a vendor-neutral, OpenTelemetry-based control plane over everything their LLM app does: every request becomes a trace of nested observations (LLM calls, tool calls, retrieval), grouped into user sessions, enriched with cost/latency/quality scores; prompts are versioned and deployed like code; datasets and evaluators (LLM-as-judge, human annotation, custom code) close the iteration loop; and the whole stack is MIT-licensed, self-hostable, and identical to what powers their cloud. Their positioning phrase: "open, self-hostable, extensible." [Why Langfuse / open-source chapter](https://langfuse.com/handbook/chapters/open-source)
4. **Corporate timeline** — built during YC W23 (Jan 2023), OSS public launch Aug 2023, $4M seed Nov 2023 (Lightspeed, La Famiglia/General Catalyst, YC), V3 Dec 2024 (ClickHouse migration), ~60% of cloud observations via OTel by 2025, **acquired by ClickHouse 2026-01-16** (same day ClickHouse announced a $400M Series D at a $15B valuation). They had Series A term sheets but sold instead. [Story](https://langfuse.com/handbook/chapters/story), [Seed blog](https://langfuse.com/blog/announcing-our-seed-round), [Joining ClickHouse](https://langfuse.com/blog/joining-clickhouse), [ClickHouse blog](https://clickhouse.com/blog/clickhouse-acquires-langfuse-open-source-llm-observability), [Reuters](https://www.reuters.com/technology/database-management-firm-clickhouse-valued-15-billion-amid-ai-boom-2026-01-16/)

## 2. Architecture

1. **Languages & app tier** — TypeScript/Node monorepo. `web/` = Next.js 14 (pages router) serving UI + tRPC + public REST APIs, Auth.js/NextAuth, Prisma ORM, Zod, shadcn/ui; `worker/` = **Express** container doing background processing (ingestion, exports, eval execution). Alpine-based Docker images published as `docker.langfuse.com/langfuse/langfuse(-worker):4`. [CONTRIBUTING.md](https://github.com/langfuse/langfuse/blob/main/CONTRIBUTING.md), [Architecture](https://langfuse.com/handbook/product-engineering/architecture)
2. **Monorepo layout** — `web/` (Next.js app), `worker/` (queue consumers + background jobs), `packages/shared/` (shared domain/DB/queue contracts + repositories), `ee/` (enterprise package consumed by web/worker), `generated/` (generated API clients — do not hand-edit), `fern/` (API definition sources), `scripts/`. Dependency direction enforced: `web → @langfuse/shared`, `ee` layered on top. [.agents/AGENTS.md](https://github.com/langfuse/langfuse/blob/main/.agents/AGENTS.md)
3. **Storage engines (4 + optional LLM API)** — **Postgres** (transactional: users, orgs, projects, API keys, prompts, datasets, judge configs), **ClickHouse** (all tracing data: traces/observations/scores; dashboards, metrics, UI tables), **Redis/Valkey** (BullMQ event queue + cache for API keys and prompts), **S3/blob** (raw ingestion event store, multimodal media, batch exports). Optional external **LLM API/gateway** connection powers playground, LLM-as-judge, and the in-app agent. All ClickHouse/Postgres must run in UTC. [Self-hosting](https://langfuse.com/self-hosting), [Architecture](https://langfuse.com/handbook/product-engineering/architecture)
4. **Ingestion pipeline (the key design)** — SDKs send spans via OpenTelemetry → Web container batches and writes raw events to S3 first, queueing only references in Redis (BullMQ) → Worker picks up from S3, enriches, flushes to ClickHouse. Consequences they call out: spikes never hit the DB directly; events are recoverable if the DB is down; API-key auth checks are Redis-cached for cheap rejection; prompts are Redis read-through cached. Long-running DB migrations are offloaded to background jobs to reduce upgrade downtime. [Self-hosting](https://langfuse.com/self-hosting)
5. **V4 data model (2026)** — single **wide, (mostly) immutable ClickHouse table**, observations-first: trace-level attributes (`user_id`, `session_id`, tags, etc.) are **denormalized onto every observation row** (propagated via OTel Baggage), `trace_id` demoted from entity to correlation handle. Motivation: at billions of rows, ReplacingMergeTree read-time dedup (`FINAL`/`LIMIT BY`) and traces↔observations joins became the dominant cost; immutability eliminated dedup entirely (initial table loads "seconds → milliseconds", dashboards "10x faster"). S3 raw-event storage cost dropped ~85% for OTel-only users because spans are immutable (batch = one object, no merge-on-read). They explicitly cite the "Wide Events" essay and Uber's ClickHouse logging platform as prior art. [Simplify for scale](https://langfuse.com/blog/2026-03-10-simplify-langfuse-for-scale), [V3 blog](https://langfuse.com/blog/2024-12-langfuse-v3-infrastructure-evolution)
6. **Evolution history worth knowing** — started on Vercel + Supabase (Next.js/Postgres); V3 (Dec 2024) moved tracing from Postgres to ClickHouse; the ingestion queue tech evolved (early V3 shipped Kafka/Redpanda in compose; current releases use Redis/BullMQ); V4 (tagged 2026-07-29, GA 2026-08-13) is the observations-first rewrite with real-time OTel ingestion (opt-in via `x-langfuse-ingestion-version: 4` header). [V3 blog](https://langfuse.com/blog/2024-12-langfuse-v3-infrastructure-evolution), [v4.0.0 release](https://github.com/langfuse/langfuse/releases/tag/v4.0.0), [V4 changelog](https://langfuse.com/changelog/2026-08-13-langfuse-v4)
7. **Deployment options** — official: **docker-compose** (local/low-scale), **Kubernetes Helm chart** ([langfuse-k8s](https://github.com/langfuse/langfuse-k8s)), **Terraform modules for AWS/Azure/GCP**; community: Render, Railway. Self-host OSS / self-host Enterprise / Cloud all run the same codebase and schema — you can move between them by adding a license key or switching endpoints. Internet access is optional (air-gap/VPC supported). [Self-hosting](https://langfuse.com/self-hosting), [Open-source chapter](https://langfuse.com/handbook/chapters/open-source)
8. **Scale claims** — Langfuse Cloud: **>80M traces/day, >5B tracing events/month, thousands of customers, petabytes of tracing data** on one multi-tenant deployment; "10+ billion observations/month" marketing claim; data processed through ClickHouse grew 19x in 2025 while nodes grew 15x. [Enterprise](https://langfuse.com/enterprise), [Simplify for scale](https://langfuse.com/blog/2026-03-10-simplify-langfuse-for-scale)
9. **License** — MIT for everything except `ee/`, `web/src/ee/`, `worker/src/ee/` (commercial "ee/LICENSE"; GitHub shows license "Other/NOASSERTION" for this reason). Core product features carry **no usage limits** in OSS. [LICENSE](https://github.com/langfuse/langfuse/blob/main/LICENSE), [Open-source chapter](https://langfuse.com/handbook/chapters/open-source)

[Version control](https://langfuse.com/docs/prompt-management/features/prompt-version-control), [Data model](https://langfuse.com/docs/prompt-management/data-model), [Webhooks](https://langfuse.com/docs/prompt-management/features/webhooks-slack-integrations), [Prompt CI/CD](https://langfuse.com/resources/engineering/prompt-cicd)

[Assistant](https://langfuse.com/changelog/2026-06-19-langfuse-assistant-public-beta), [MCP changelog](https://langfuse.com/changelog/2026-05-29-mcp-update), [MCP docs](https://langfuse.com/docs/api-and-data-platform/features/mcp-server)

## 4. Integration surface

1. **First-party SDKs** — **Python (v4)** and **JS/TS (v5)**, both rebuilt on OpenTelemetry internals (separate repos `langfuse-python`, `langfuse-js`; models generated with Fern); fully async batching with explicit `flush()` for short-lived processes. [SDK overview](https://langfuse.com/docs/observability/sdk/overview)
2. **OpenTelemetry as the backbone** — Langfuse is an **OTel backend**: OTLP/HTTP ingestion at `/api/public/otel` (JSON + protobuf; **no gRPC**), Basic auth with `pk-lf-…:sk-lf-…`, local endpoint since v3.22. OTel-native SDK v4 is a thin layer over official OTel clients that maps spans (spans/generations/events) and defaults to LLM-relevant spans (`gen_ai.*`, known instrumentors). [OTel integration](https://langfuse.com/integrations/native/opentelemetry)
3. **Span attribute schema (their contract)** — `langfuse.*` namespace takes precedence over generic conventions: trace-level (`langfuse.user.id`, `langfuse.session.id`, `langfuse.trace.tags`, `langfuse.trace.metadata.*`, `langfuse.release`), observation-level (`langfuse.observation.type` = span|generation|event, `langfuse.observation.input/output`, `langfuse.observation.model.name`, `langfuse.observation.usage_details`, `langfuse.observation.prompt.name/version` for linking managed prompts, `langfuse.observation.cost_details`). Interop mappings: OTel **GenAI semconv** (`gen_ai.request.model`, `gen_ai.usage.*`, `gen_ai.prompt/completion`), OpenInference (`input.value`/`output.value`), MLflow (`mlflow.spanInputs/Outputs`), `llm.*` (OpenLLMetry) — plus a prototype-pollution guard that silently drops `__proto__`/`constructor`/`prototype` attribute keys. [OTel mapping](https://langfuse.com/integrations/native/opentelemetry)
4. **Trace-attribute propagation** — because aggregations run on observations, `userId`/`sessionId`/tags/metadata must be on *every* span; recommended pattern is OTel **Baggage + BaggageSpanProcessor**, or SDK helpers `propagate_attributes()`. This is exactly what enables their V4 single-table design. [OTel integration](https://langfuse.com/integrations/native/opentelemetry)
5. **Framework/provider integrations** — native: LangChain/LangGraph, LlamaIndex (+ Workflows), OpenAI SDK, Vercel AI SDK, CrewAI, AutoGen, Semantic Kernel, Pydantic AI, Spring AI, smolagents, DSPy, LiteLLM (proxy-based logging), etc. Any other language (Go, Java, C#, Ruby) via standard OTel SDKs or instrumentor libraries (OpenLLMetry, OpenLIT, Arize, MLflow). [Integrations](https://langfuse.com/integrations), [OTel languages guide](https://langfuse.com/resources/engineering/opentelemetry-languages)
6. **APIs, exports, webhooks, MCP** — public REST API with published OpenAPI spec (annotation queues, prompts, datasets, scores, observations, metrics APIs), query-via-SDK (`client.api` generated from OpenAPI), batch export to blob storage, PostHog/Mixpanel, prompt webhooks/Slack, hosted MCP server (read+write) + docs MCP; community MCP clients exist (e.g. `langfuse-mcp` on PyPI). [Public API](https://langfuse.com/docs/api-and-data-platform/features/public-api), [MCP docs](https://langfuse.com/docs/api-and-data-platform/features/mcp-server)

## 6. Local runbook (canonical docker-compose path)

1. **Requirements** — git + Docker/Desktop. Docs' VM sizing for a single node: **≥4 cores / 16 GiB RAM (e.g. t3.xlarge), ~100 GiB disk**; per-container minimums: web 2 CPU/4 GiB, worker 2 CPU/4 GiB, Postgres 2 CPU/4 GiB (plus ClickHouse and Redis needs). [Docker compose guide](https://langfuse.com/self-hosting/deployment/docker-compose), [Scaling guide](https://langfuse.com/self-hosting/configuration/scaling)
2. **Exact commands** —
   ```bash
   git clone https://github.com/langfuse/langfuse.git
   cd langfuse
   # edit docker-compose.yml: every line marked "# CHANGEME"
   #   (SALT, ENCRYPTION_KEY `openssl rand -hex 32`, NEXTAUTH_SECRET,
   #    CLICKHOUSE_PASSWORD, REDIS_AUTH, MINIO/postgres creds)
   docker compose up
   # wait ~2–3 min until langfuse-web-1 logs "Ready"
   # open http://localhost:3000
   ```
   [Docker compose guide](https://langfuse.com/self-hosting/deployment/docker-compose)
3. **What compose v4 actually starts (verified from `main`)** — 6 services: `langfuse-web:4` (:3000), `langfuse-worker:4` (:3030 health), **ClickHouse 25.12** (127.0.0.1:8123/9000), **MinIO** (chainguard image; :9090→9000 S3 API, :9091 console, pre-creates the `langfuse` bucket), **Redis 7** (BullMQ, `noeviction`), **Postgres 17** (TZ/PGTZ=UTC forced). All backends bound to 127.0.0.1; only web (:3000) and MinIO (:9090) are meant to be exposed. Notable env knobs: `LANGFUSE_INIT_ORG/PROJECT/USER_*` (seed a project + API keys on boot), `LANGFUSE_AI_*`/`LANGFUSE_IN_APP_AGENT_*` (LLM config for assistant/judge/playground), `LANGFUSE_OBSERVATION_FIELD_SIZE_LIMIT_BYTES` (2 MiB default), optional S3 batch export bucket. [docker-compose.yml](https://raw.githubusercontent.com/langfuse/langfuse/main/docker-compose.yml)
4. **What breaks (from docs + issue tracker)** —
   - **Non-UTC timezones** on Postgres/ClickHouse → wrong/empty query results (docs-level footgun).
   - **ClickHouse OOM** in compose deployments (e.g. 5.4 GiB memory-limit aborts during async inserts) — [langfuse-docs#2006](https://github.com/langfuse/langfuse-docs/issues/2006).
   - **Idle ClickHouse CPU burn** after V3 even with no traffic; devs who ran V2 locally report it's no longer laptop-friendly — [langfuse#6572](https://github.com/langfuse/langfuse/issues/6572).
   - **Port 9000 conflicts** (ClickHouse native TCP vs local MinIO/other services) — [#5432](https://github.com/langfuse/langfuse/issues/5432), [#4867](https://github.com/langfuse/langfuse/issues/4867).
   - **Multimodal uploads fail** because MinIO isn't reachable from outside the Docker network for direct client uploads (compose guide's own troubleshooting note).
   - **2–3 minute cold start**; secrets left as defaults are a real risk if :3000/:9090 are exposed; playground/judge/assistant silently unavailable until an LLM connection is configured; worker scaling guidance is CPU-load-based (>50% on 2 CPU ⇒ scale). [Troubleshooting & FAQ](https://langfuse.com/self-hosting/troubleshooting-and-faq), [Scaling](https://langfuse.com/self-hosting/configuration/scaling)
5. **Local OTel ingestion** — point any OTLP/HTTP exporter at `http://localhost:3000/api/public/otel` with Basic auth (`pk-lf-…:sk-lf-…` base64) and `x-langfuse-ingestion-version: 4` to get real-time (vs ≤10 min delayed) ingestion. [OTel integration](https://langfuse.com/integrations/native/opentelemetry)

## 7. Top 8 concrete lessons for HandoffGraph (Go + SQLite, local-first)

1. **Adopt an observations-first, denormalized read model — trace as correlation ID, not entity.** Langfuse's two biggest scaling wars (ReplacingMergeTree dedup, traces↔observations joins) both came from treating the trace as a second entity; V4 denormalizes `user_id`/`session_id`/tags onto *every* observation row and calls `trace_id` a correlation handle. **Mapping:** HandoffGraph's trace materializer should emit a *wide, sorted* derived table in SQLite (one row per event with session/agent/turn columns copied on), built by the deterministic reducer from the append-only spine — no joins on the hot UI path, and re-derivation stays pure because inputs are immutable events. Their Wide-Events/Uber rationale is a good citation for an architecture-doc ADR. [Simplify for scale](https://langfuse.com/blog/2026-03-10-simplify-langfuse-for-scale)
2. **Make immutability a first-class ingest contract.** They found that immutable spans (OTel) removed read-time dedup and cut S3 event-store costs ~85%; only genuinely mutable things (bookmarks, publish flags) use lightweight updates. **Mapping:** HandoffGraph's append-only event spine already matches this — codify "derived rows are immutable; corrections are new events + reducer re-run," and keep the rare mutable flags (archived/starred) in a separate small table updated in place. [Simplify for scale](https://langfuse.com/blog/2026-03-10-simplify-langfuse-for-scale)
3. **Speak OTLP/HTTP + GenAI semconv, with your own override namespace.** Their winning move: accept standard OTel spans (`/api/public/otel`, Basic auth, HTTP/JSON+protobuf) *and* layer a `langfuse.*` attribute namespace that overrides conventions, with explicit interop mappings for OpenInference/MLflow/OpenLLMetry, plus a deny-list for dangerous attribute keys. **Mapping:** give the Go server an OTLP-HTTP ingestion endpoint; define `handoffgraph.*` attributes (adapter, session file hash, tool name, diff stat, checkpoint id) over GenAI semconv so any OTel client can feed HandoffGraph; mirror their reserved-key guard with a fail-closed attribute sanitizer (consistent with our redaction posture). [OTel integration](https://langfuse.com/integrations/native/opentelemetry)
4. **Prompts/agent configs as immutable versions + mutable labels.** Versions are append-only (1,2,3…), labels (`production`, `latest`, custom) are repointable pointers, clients cache with background revalidation, and every change can trigger webhooks/CI gated on dataset evals. **Mapping:** store checkpoints/prompt+system-config snapshots in HandoffGraph as content-addressed, immutable objects referenced by events; labels become a tiny mutable pointer table; the embedded UI diffs two versions; export labels in `hg` CLI for "what config produced this session" queries. [Prompt version control](https://langfuse.com/docs/prompt-management/features/prompt-version-control), [Data model](https://langfuse.com/docs/prompt-management/data-model)
5. **A universal "score" primitive for all quality signals.** One object — numeric/categorical/boolean, attachable to trace/observation/session, tagged with source (human/API/external) — powers user feedback, annotation queues, LLM judges, and CI checks in one analytics surface. **Mapping:** model HandoffGraph evidence checks (verify pass/fail, test outcome, review verdict, human annotation) as scores attached to checkpoints/spans; this gives uniform pass-rate-over-time analytics per adapter/model/branch without inventing per-check tables. [Scores overview](https://langfuse.com/docs/evaluation/scores/overview), [Core concepts](https://langfuse.com/docs/evaluation/core-concepts)
6. **Build the AI features on your own MCP tool layer.** Langfuse's in-app Assistant (beta Jun 2026) is literally the hosted MCP server (read+write tools over observations/metrics/scores/datasets/comments) connected to their own product; a docs-MCP and community CLIs exist too. **Mapping:** HandoffGraph's 9-tool local stdio MCP server should be the *only* query layer — the embedded web debugger should call the same tools (in-process) that Claude Code/Codex/Pi call over stdio; add observation/score/dataset-style tools and keep the tool list self-describing. This is a two-frontend/one-backend pattern proven at their scale. [MCP docs](https://langfuse.com/docs/api-and-data-platform/features/mcp-server), [Assistant](https://langfuse.com/changelog/2026-06-19-langfuse-assistant-public-beta)
7. **Raw-payload-first persistence + background upgrades.** Ingestion writes raw payloads to blob storage before processing, queues only references, and long migrations run in the background so upgrades don't block reads. **Mapping:** on import, persist the raw adapter payload (or its hash+payload) into the spine before materialization, make re-import idempotent via deterministic event IDs (we already do this for hooks), and move any future schema migration of derived tables into a background `hg migrate` that doesn't block ingest. [Self-hosting](https://langfuse.com/self-hosting)
8. **Dual-key project-scoped auth + cheap key validation.** `pk-lf-…`/`sk-lf-…` Basic-auth key pairs scoped to a project, with a cache layer so unauthorized requests are rejected without touching the DB. **Mapping:** for the Cloudflare Workers/D1 foundation, mirror this: public key embedded in hook configs, secret key server-side, and an edge-cached/D1-lookup key table; keep hook installers merge-safe (never overwrite) as now, but let revocation be a key-table toggle, not a config rewrite. [Self-hosting](https://langfuse.com/self-hosting), [Public API](https://langfuse.com/docs/api-and-data-platform/features/public-api)

*(Bonus: their environments/tags/release/version attribute taxonomy is a good checklist for session metadata — HandoffGraph can adopt `environment` (local/CI), `release` (git SHA), `tags` (branch, model) as standard, filterable columns.)*

## 8. What they DON'T do — differentiation space for HandoffGraph

1. **No coding-agent focus.** Langfuse traces *LLM applications* (APIs, chatbots, RAG). It has no concept of coding-agent session files (Claude Code/Codex/Pi transcripts), no adapters consuming local agent storage, no merge-safe hook installers, no turn/tool-call/file-edit semantics. **HandoffGraph owns "session debugging for AI coding agents" outright.**
2. **No evidence/verification model.** Scores and annotations are *assertions*; nothing verifies that a trace is complete, tamper-evident, or re-derivable, and determinism of read models is an internal concern, not a user-facing guarantee. HandoffGraph's deterministic-hash, re-derivable, evidence-based checkpoints ("this session state is verified, no LLM involved") has no Langfuse equivalent. [Evaluation docs](https://langfuse.com/docs/evaluation/overview)
3. **Redaction is not fail-closed by design.** Masking = client-side helpers (OSS) or server-side masking (paid EE); there's no "redaction error ⇒ refuse to export" contract. HandoffGraph's fail-closed redaction is a differentiator for teams piping agent transcripts (full of secrets/code) anywhere. [Self-host matrix](https://langfuse.com/pricing-self-host)
4. **Heavy for local use.** Six containers, four storage engines, UTC constraints, ClickHouse OOM/idle-CPU/port conflicts, 2–3 min cold start, 16 GiB-recommended hosts. There is no single-binary laptop mode. A pure-Go single binary with embedded SQLite + embedded UI is a categorically simpler story for the "debug my agent on my machine" job. [#6572](https://github.com/langfuse/langfuse/issues/6572), [#2006](https://github.com/langfuse/langfuse-docs/issues/2006), [Docker compose guide](https://langfuse.com/self-hosting/deployment/docker-compose)
5. **AI features require LLM keys.** Playground, LLM-as-judge, and the Assistant all need a configured LLM connection; offline they're dead weight. HandoffGraph's no-LLM checkpoints work offline by construction. [Self-hosting](https://langfuse.com/self-hosting)
6. **No cross-session continuity/handoff model.** A "session" is just a grouping of traces within one app; there's no model for *handing off context between agents or sessions* (continuity, provenance OBSERVED/DECLARED/INFERRED), which is HandoffGraph's core claim.
7. **No code-aware artifacts.** Inputs/outputs are JSON blobs; no first-class diffs, worktrees, file edits, or tool-call→filesystem mapping — the actual content coding-agent debugging revolves around.
8. **MCP is cloud-first.** The official MCP server is the hosted one (auth via cloud project keys); self-hosted/local-first MCP debugging is underserved — HandoffGraph's local stdio MCP server fits where agents actually run (the developer's laptop). [MCP docs](https://langfuse.com/docs/api-and-data-platform/features/mcp-server)

**Caveat:** don't out-scope — Langfuse's eval/judge/playground breadth and 100+ integrations come from a funded team at cloud scale; HandoffGraph should copy its *data-model and API contracts* (lessons 1–8), not its product breadth.
